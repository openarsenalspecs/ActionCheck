# Contributing to ActionCheck

Thank you for your interest in contributing to **ActionCheck** – *Every Action Logged. Every Deviation Noted.*  

This document outlines how to contribute code, data, or documentation to the project, as well as the expectations for attribution, licensing, and workflow compliance.

---

## Getting Started

1. **Fork & Clone**  
   - Fork the repository on Codeberg and clone it locally to your machine.  

2. **Branching**  
   - Create a new branch for each feature, bug fix, or improvement.  
   - Branch names should be descriptive, for example: `feature/promise-tracker`, `fix/vote-data-parsing`.  

3. **Environment Setup**  
   - Follow the installation instructions in `README.md` to set up your development environment.  

4. **Coding Standards**  
   - Write clear, readable, and well-documented code.  
   - Maintain inline attribution headers in new files if applicable.  
   - Ensure contributions follow project conventions and best practices.  

5. **Testing & Verification**  
   - Test your changes locally before submission.  
   - Ensure new features do not break existing functionality.  
   - Add tests for any significant functionality whenever possible.  

6. **Pull Requests**  
   - Push your branch to your fork and open a pull request.  
   - Include a detailed description of your changes, references to issues, and any relevant data sources.  
   - Be responsive to feedback and make requested updates promptly.

## Reporting Issues

- Open an issue in the Codeberg repository for bugs, missing data, or feature requests.  
- Provide as much detail as possible, including steps to reproduce, screenshots, or relevant data sources.  

---

## Code of Conduct

- Be respectful and professional in all interactions.  
- Maintain a focus on transparency, accuracy, and accountability.  
- Contributions that violate the license, attribution requirements, or project mission may be rejected.
